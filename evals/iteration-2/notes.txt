INTERPRETATION - THE HONEST READING: on Claude Opus 5, the behaviours this skill prescribes appear to be largely already present. Two independent eval sets, one easy and one verified-hard, both failed to separate the configurations across 43 total assertions. The remaining hypotheses are that the value is model-dependent (plausibly real on weaker models, undetectable here), or that it shows up only on problems harder than a single agent turn can solve at all. Nothing here supports a claim that the skill improves Opus 5's outcomes.
QUALITATIVE DIFFERENCES PERSIST BUT DO NOT REACH THE SCOREBOARD: with_skill consistently did more - eval-0 fixed all three broken handlers behind one shared helper where baseline fixed one and flagged two as product decisions; eval-1 ran a 39-case edge sweep and a difflib check proving 0 original test lines were modified; eval-3 ran 30 randomized method shuffles. Whether that extra work is worth 1.5x tokens is a judgement call, and on these fixtures it bought no additional passing assertions.
TWO GRADER BUGS WERE FOUND AND FIXED, BOTH THE SAME MISTAKE: 'test file must be byte-identical' (iteration 1) and 'Ran 9 tests' (iteration 2) each penalised an agent for ADDING regression tests. Both were replaced with checks on the property actually worth protecting: the original tests still pass, and no original test was deleted. A grader written to catch cheating must not also catch improvement.
